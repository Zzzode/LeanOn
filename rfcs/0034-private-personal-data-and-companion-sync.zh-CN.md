# 私有个人数据与搭档同步

[English](0034-private-personal-data-and-companion-sync.md) · 简体中文

## 决策

依据明确工作区授权完成个人和双人流程。
本 RFC 保持 Proposed；不授权提交、发布或生产部署。
保留视觉语言和认可底栏。
健康数据默认私有，独立定向授权，不建立共享热量预算。

## 存储和备份

保留记录 schema 2；版本 1 个人集合使用修订检查和持久回执。
偏好不是过敏安全判断；围度缺失保持未知，不做诊断推断。
原生将明确选择的图片重绘为脱敏 JPEG，与元数据原子保存在同一认证加密集合。
AES-256-GCM 保护记录和个人数据，Keychain/Keystore 保护原生密钥。
兼容读取旧明文，仅下一次明确写入时加密。
验收不查看或迁移正式应用记录。

备份包含记录、自定义食品、收藏/最近食品、个人数据和实际存储照片，排除所有凭据和密钥。
版本 1 扁平信封采用 PBKDF2-HMAC-SHA256（600000 次）、随机盐（16 字节）、AES-256-GCM nonce（12 字节）和精确 UTF-8 AAD `LeanOn backup v1`。
密码为未经归一化的精确 UTF-8（12–1024 字节）。
上限：序列化信封文件 64 MiB，单照片 20 MiB，总照片字节 32 MiB，1000 张照片。
认证后解析、完整验证后写入，保留现有合法历史语义。
预览产生绑定当前两个修订号的五分钟原生令牌。
恢复检查修订号，使用持久恢复/回滚日志，并将修订号推进至当前和导入值之上。
选择器取消独立返回；打开分享界面不是文件写入成功。

### 原生预览渲染

图片辅助节点存在或 URI 成功，不代表真实像素已经显示。
iOS 宿主使用专用 Lynx 加载器，仅访问已批准的 own／partner 预览能力。
Android 使用匹配的 Lynx3.9 图片服务及 Fresco2.3，并在原生端授权请求；该 SDK 依赖用于实际 JPEG 显示。
不向页面暴露一般网络、内容提供者或任意文件图片加载器。
解码及交付前验证已签发能力、规范缓存子路径、无符号链接、摘要、前台状态及当前范围代次。
禁用二次磁盘缓存，在后台、删除、授权撤销及范围变更时失效解码内存。
先撤销内存能力，再执行可能失败的文件清理；清理失败不能保留图片访问授权。
真实原生像素检查须与元数据、加密字节、URI 及辅助节点断言一起记录。

## 账户和加密同步

使用真实本地 Node HTTP/密码学/文件系统中继，不选择生产供应商。
存储 scrypt 密码校验值、加密载荷和路由元数据，不接收健康明文/群组密钥。
服务器会话三十分钟过期，不持久化。
随机原生设备证明防止公开设备 ID 冒用授权。
新设备须已有设备确认对应邀请接收者/证明。
仅客户端的邀请秘密用独立 HKDF-SHA256 上下文派生证明和包装密钥；中继不收到秘密或包装密钥。
接受仅待确认；创建者确认后建立最多两个账户的家庭。
所有类别默认关闭：目标、趋势区间、连续性、餐食、照片、经期、精确体重、围度和鼓励。
健康分享定向授权；鼓励须双方开启。

保险库同步包含真实加密照片字节；搭档图片须当前关系/授权及原生加密缓存。
载荷 AAD 是数组 `["leanon-change-v1",groupId,epoch,ownerId,deviceId,id,recordId,category,kind,updatedAt,deleted]` 的精确紧凑 UTF-8 JSON。
使用幂等、墓碑、确定性冲突和持久游标。
原生收到数据/游标落盘后才 ACK；接收者 ACK 才算送达。
按实体身份和各自时钟合并快照，保留并发新增并重算派生营养。
准确记录的撤销可因果恢复对应删除令牌；其他墓碑仍权威生效。
登录不绑定本机记录：须预览命名账号并明确同意经过修订检查的导入。
本地绑定和保留保险库密钥同时绑定端点域与账号；更换端点须重新同意。
上传健康内容前，将中继授权与本设备持久明确同意取交集。
新设备的默认空值不能抹掉账号已有配置。
刷新授权并清撤销缓存；解除关系清服务器密文、搭档缓存和家庭密钥。
撤销不能擦除已经留存的副本。
删除账户须密码及明确保留/删除本地选择；认证材料及搭档缓存始终清除。

### 可恢复账号删除

发送 HTTP 前先持久保存加密删除意图，固定端点/账号、本机数据选择及两个初始修订号。
不保存密码，不向 Lynx、事件或备份暴露独立32字节删除证明。
中继以同一个事务删除账户并建立有容量上限的回执，用包含操作ID、账号ID及证明的独立域哈希认证。
会话撤销后仍可查询回执；返回成功前重新完成文件持久性屏障。
没有回执、会话过期、HTTP失败及未知结果均不能确认删除。
明确输入密码重试时沿用同一操作；重新认证后还须核对账号身份。

匹配持久回执后，先清认证和搭档状态，再执行可失败清理。
使用已有多存储日志、两个初始修订号，将记录/个人集合删除与 companion 的 localDataCleared 标记一起提交。
本机数据有变化时须重新明确选择并同意当前修订版本，恢复不能静默擦除新增数据。
localDataCleared 持久后，重试绝不重复清空。
若包装密钥清理失败后出现新文件，保留新文件及密钥，拒绝危险清理并维持待恢复状态。
先持久保存 local-complete，再确认中继回执；确认响应丢失也不能重复删除。
未解决的删除意图阻止其他 companion 操作。

### 有界照片分页

自有或共享图库每页最多挂载四张照片，导航及页数使用本地化文本。
换页时卸载旧读取者，拒绝旧页迟到结果。
1000张存储上限与已挂载图片的内存预算分别验收；仍须实际原生资源证据。

## 验收

验证共享合同、原生加密/篡改拒绝、原子恢复、实际 HTTP 授权及隔离双原生交换。
记录源码/包哈希及标注设备、语言、外观的实际原生截图。
小屏、文字缩放、读屏、跨午夜/时区和生命周期单独验收。
验收不批准系统相机、健康、蓝牙、通知或图库权限。
实体硬件、实际权限依赖的送达、签名真机发布及生产部署单独验收。
供应商、恢复、外部滥用防护和大载荷流式传输保留为运维决策。
参见[协议](../server/companion/protocol.zh-CN.md)及[执行清单](../docs/full-product-2026-10-07/plan.zh-CN.md)。

## 容器搬迁后的原生存储密钥

原生角色使用稳定逻辑Keychain账号，不依赖沙箱绝对路径。
既有密文认证其精确稳定密钥，或同一应用service／角色下有界旧别名中唯一能够认证的密钥。
迁移以insert-if-absent复制相同32字节DEK，不重新加密数据、不覆盖稳定别名、不丢弃密文、不移除旧别名。
启动和前台恢复先认证所有当前文件及日志历史密文，要求每个角色使用同一DEK，提升已认证密钥，再写恢复文件。
读取缺失／明文文件不创建凭据；锁定、损坏、歧义和复制失败保持不可用并保留原数据。
local-complete删除在ACK前核验已不存在的角色文件没有未确认密钥残留；新建文件及密钥保留，不再次擦除。
没有认证密文的孤立旧密钥保持待恢复，不猜测归属或静默丢弃意图。
Debug夹具路径覆盖仍隔离并保持显式路径命名。
