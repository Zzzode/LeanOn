# 个人建档与可恢复的每日记录

[English](0032-personal-daily-records.md) · 简体中文

## 摘要

完成本地个人日用闭环：建立资料、记录所选日期、修改历史、恢复删除并重启不丢数据。
用户已授权在当前包含既有修改的工作区实施；本文未合并，不授权提交或发布。

## 动机

现有缺失文件初始化会复制演示健康数据。
饮食只能按日累计，缺少资料修改，保存日期跟随当时的今日状态。
这些行为阻碍日常使用与可靠的历史纠错。

## 用户体验

新安装为空，由用户填写自己的资料，不用示例资料或记录代替答案。
取消或中断建档不完成建档，也不保存半份资料。
Diary 选择本地日期，统一查看与补录体重、饮食、运动和饮水。
打开的草稿固定所选日期，跨午夜、前台恢复或时区变化不会偷偷改变保存日期。
新饮食显示真实保存的份量和餐次，旧摄入明确显示为旧版每日汇总。
删除先确认，再可撤销；重启后仍可在最近删除中恢复。
恢复遇到同一 ID 或日记录已有新数据时拒绝覆盖。

## 数据与事务

版本2增加 revision、setupCompleted、可空资料/目标、指导模式与显式可空筛查标记。
保留食物目录、收藏/最近、来源所有权与健康平台投影。
intakeEntries 保存稳定 ID、本地日期、餐次、食物名称、份量与营养。
legacyIntake 保留旧每日汇总，不伪造组成它的食物。
既有 intake 由有效新条目与旧汇总重新计算，供图表和健康导出使用，避免重复计入。
体重和饮水有稳定身份，外部镜像继续只读。
未知版本或损坏的既有文件保留字节并明确失败。
读取旧数据可先生成未落盘的兼容投影；迁移与所请求的修改一起原子替换文件。
既有本地记录，包括可能来自旧演示的记录，全部保留；应用不能可靠猜测哪些是用户认可的真实记录。
正式空初始化与显式隔离 QA fixture 分开。

records.getSnapshot 返回原生时钟确定的今日与完整快照。
records.mutate 接收操作 ID、预期 revision 与带类型的修改：资料、体重/饮水、运动/饮食、删除或恢复。
真实运行发现 Lynx 原生参数转换会丢弃 map 中显式的 null 值，因此 transport 对该方法使用私有 JSON 字符串封装。
原生适配器先解码原始请求再校验，保留缺少字段与显式 null 的区别，公开的类型化 RPC 合约不变。
两端校验相同的日期、数值、来源归属与建档安全规则。
新修改拒绝未来日期，迁移保留已有未来记录。
记录、revision、操作回执及删除墓碑同时原子落盘后才回报成功与发事件。
相同操作重试返回当前快照及原回执，不重复效果，重启后仍有效。
同一操作 ID 换内容或过期 revision 明确失败。
本版不淘汰操作回执。
墓碑保留实际记录、来源、删除 revision 和原生时间；恢复通过冲突检查后才移除墓碑。
本轮不增加永久删除或自动清空回收记录。
既有 RPC 保持兼容，共享用户写入切换新事务。

## 日期与指导

原生当前时间及系统时区为准。
前台、本地下一个午夜、显著时钟/日期和时区变化时更新；共享页面可请求新快照。
本地日期是日历标签，不是 UTC 时刻；旅行时不重写历史日期。
草稿日期独立于 Today；刷新不把记录移动到另一天。
修改资料不隐式修改体重；可选初始体重仅允许首次成功建档。
自动减重指导要求至少20岁、全部筛查明确为否、支持的当前/目标体重且没有低 BMI 目标。
孕期、哺乳期、饮食失调风险或未回答筛查保留记录功能，不显示热量缺口目标；适当提示专业支持。
20岁门槛是保守产品选择，不是诊断，也不表示所有成年人都应减重。
[NIDDK 工具](https://www.niddk.nih.gov/bwp) 排除未成年人及孕哺期；[CDC 成人 BMI 分类](https://www.cdc.gov/bmi/adult-calculator/bmi-categories.html) 从20岁适用，强调 BMI 是筛查而非诊断。
保留既有热量公式与基础代谢下限，不奖励极低摄入或将其视为计划成功。

## 代价与替代

持久回执和可恢复删除会增加本地 JSON 大小，并保留已删除健康数据，直到未来明确设计永久删除。
旧汇总不能恢复丢失的餐次身份，只能作为汇总纠错，不能猜出食物。
并发原生变更后，严格 revision 检查可能要求刷新重试。
本地文件仍未加密，沿用 RFC0031 的披露，本轮没有云服务。
只有日汇总不足以逐条修改，猜测食物会制造历史。
revision 与持久操作 ID 不引入新数据库即可支持确定性重试；墓碑比内存撤销提示更可靠。

## 未决与实施

真机可访问性、大量历史及未来加密存储另行验收。
实际通知、相机、HealthKit 或蓝牙授权必须先经用户明确批准，不在本轮 QA 中。
先冻结共享模型与验收矩阵，再实现两端事务与建档/历史页面。
用隔离 fixture 验证取消建档、迁移、坏文件/写失败、重复保存、过期提交、恢复冲突、补录、时区与跨午夜。
支持范围内执行双语言、浅深色实际原生 UI 闭环，区分按钮与存储/SDK 测试。
将构建身份、原图、代码依据与通过/未测矩阵保存至 Library，不提交、推送或发布。
