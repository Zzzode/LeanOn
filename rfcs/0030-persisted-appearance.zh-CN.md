# Lynx 与原生宿主协同持久化外观

[English](0030-persisted-appearance.md)

## 摘要

提供跟随系统、浅色和深色，由原生持久化一个偏好，并向页面、原生表面和键盘共享实际主题。

## 动机

仅修改 CSS 会使导航、输入和启动背景不一致。
异步读取偏好还会先绘制错误主题。

## 用户行为

设置默认跟随系统，可明确选择浅色或深色。
成功选择在重新启动后保留，不改变记录或语言。
仅在跟随系统时响应系统外观变化。
保留已认可原生底栏几何与动效，按需调整材质和对比。

## 技术约定

宿主拥有偏好 `system | light | dark` 和实际外观 `light | dark`。
加载 Lynx 前通过初始化数据注入 `appearancePreference` 和 `appearance`，与语言和宿主记录并列。
`app.getAppearance` 返回 `{ preference, resolved }`。
`app.setAppearance` 接收 `{ preference }`，先验证再持久化、更新原生界面，并返回 `{ success: true, preference, resolved }`。
`app.appearanceChanged` 在偏好或实际系统主题改变后向全部已挂载容器广播同一状态。
页面校验事件，使用集中 CSS/SVG 调色板，切换中显示等待或错误。
明确浅色/深色偏好必须与实际外观一致。
Lynx transport 对所有 RPC 都传入请求位置和回调，包括无参数请求；原生导出方法必须匹配这两个参数。
原生集成暴露行内 CSS 变量配色缺失，因此构建从共享调色板生成明确的主题选择器，SVG 内容使用明确填充颜色。

iOS 在挂载窗口前恢复隔离 QA 或正常偏好，在主线程更新容器、导航、底栏和原生输入。
恢复跟随系统必须读取底层设备外观，不能读取已被窗口覆盖的 trait。
Android 在渲染前恢复偏好，协调应用夜间模式、原生界面及配置变化，保持路由和打开草稿。
QA 偏好与记录均与正常应用隔离。

## 代价

原生与 Lynx 表面需协调更新并处理生命周期。
iOS 系统启动页跟随系统，无法直接读取应用单独偏好，其过渡应作为独立验证边界。

## 取舍

原生拥有偏好与现有语言、能力边界一致，避免页面再建持久化层。
CSS 媒体查询不能控制原生键盘，也不能在渲染前恢复应用单独偏好。

## 待验证

两平台原生截图与交互需验证键盘、Back、弹层和重启。
大字与辅助技术需要独立验证，不能由配色检查代替。

## 实施

先完成浅深色静态设计，再扩展桥接、页面 token、设置与两平台宿主。
运行工作区 typecheck、build、Rstest，原生单元/构建及受支持隔离 UI 检查。
静态提案与真实运行证据分别保存 Library，不提交或推送。
