# 浅色与深色外观实现

[English](README.md)

本实现检查点对应完整的 [v3 双模式设计](../design-language-v3-dual/README.zh-CN.md)。
原生验收已完成，下方明确覆盖边界。
查看[实现报告](implementation-review.zh-CN.html)、[真实 24 屏总览](native-24-screen-overview.png)与[证据清单](evidence-manifest.json)。

原生宿主持久化“跟随系统、浅色、深色”偏好，并在每个 Lynx 页面挂载前注入实际外观。
Settings 提供三种选择、保存中与失败反馈，以及当前实际模式。
内容、表单和 SVG 图形共享同一配色表。
保留已认可的原生底栏形状与动效。
伴侣连接、实际送达的鼓励和账号登录仍是不可用功能。

## 证据边界

静态设计稿与真实原生截图分别交付。
首轮原生集成在两平台暴露 CSS 变量配色失效；这些截图是失败证据，不能作为验收结果。
构建与配色测试无法独立证明原生视觉、键盘、触控或读屏行为。
原生 QA 使用隔离的合成记录存储。
验证流程不打开或修改正常用户记录存储。

工作区 typecheck、build 及 222 个测试通过。
Android 的 60 个原生测试通过，最终采集十二屏并复验五项外观切换。
iOS 的 23 个原生测试通过；上一版 bundle 的五个完整 UI 用例、最终键盘连续性及最终六屏/重启持久化用例通过。
最终 iOS 读取错误已在浅深两模式实际采集。
逐图清单标注较早的表单和空态构建，不将它们冒充最终 bundle 截图。
Android 表单交互、读屏遍历、大字号、加载/写入失败及保存中原生 Back 尚未验收。
静态稿使用固定示例内容；实际页面依据原生安全区、平台界面、翻译和 QA 记录排版。

本检查点不包含提交、推送或部署。
