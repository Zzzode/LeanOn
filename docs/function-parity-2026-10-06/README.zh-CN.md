原生能力清单必须合法，页面才启用写入；扫码必须同时支持相机、查询和食物存储。
两端动态推导本地日期、小时与连续记录天数，不改变历史记录或资料。
Android 写入加锁并原子保存，校验非法日期、类型与食物归属。
能力表只纠正虚假 TODO 声明，保留所有已有实际 Android 功能。
原 TODO 调用明确返回不可用错误，不再永久等待。

## 双方尚缺的产品能力

建档、资料与目标修改、历史日期选择、逐餐身份及纠错/删除，两端均未实现。
按日体重覆盖、摄入累计不能描述成完整记录增删改。
账号及真实伴侣关联、同意、消息送达和云同步均缺失，需要独立设计。
能力名称、源码与 fake client 测试不等于硬件就绪。
读屏、大字号、小屏/真机及保存中原生 Back 仍需独立验收。

## 后续可靠性批次

Android 设置在首次成功写入时，从旧 SharedPreferences 迁移到加锁的原子 JSON 文件。
设置损坏时保留字节并阻断写入；启动、前台、worker 和 module 均正确处理错误。
开启提醒与 Health Connect 验证原生权限，不仅依赖 UI。
提醒成功等待 WorkManager 确认及设置落盘，调度失败时尽力回滚。
Health Connect 在导出前持久预留版本：首次2覆盖旧固定1，内容不变重试保持版本，修改/恢复旧内容递增。
导出及 provider 删除串行；失败不会盖完整同步成功时间。
开启偏好的回滚不撤销已经完成的 provider 写入或合法导入镜像。

扫码区分相机权限/不可用、商品查询、缺热量和商品存储失败。
模拟器相机失败不再显示 Open Food Facts 网络错误。
提醒加载/读取失败隐藏未知开关和时间、禁用保存，保留取消与重试。
共享 UI 不再在原生读取失败时用猜测的默认提醒冒充实际设置。
