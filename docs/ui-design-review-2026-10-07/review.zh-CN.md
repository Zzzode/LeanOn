# LeanOn 最新 UI：深入设计评审

[English](review.md) · [简体中文](review.zh-CN.md) · [真实页面总览](annotated-main-overview.png) · [表单总览](annotated-forms-overview.png)

结论：当前界面已经有可信的记录与恢复流程，但还没有形成鲜明的日常任务层级。
距离成熟设计的主要差距是信息编排、状态表达和交互一致性，而非缺少视觉效果。
保留已认可的原生底栏；内容区应向它清楚、克制的秩序靠拢。
本轮仅评审、采集与提出方案，没有修改业务/UI 源码，没有 commit、push 或部署。

## 先看这五项

1. **P1 · Diary 的控件比日记更突出。** 英文 iPhone SE 首屏里，日期、输入框、查看按钮、前后日与历史入口占据大部分空间，摄入卡刚出现，条目尚不可见。用户进入日记却先遇到日期工具。压成一条「前一天—当前日期—后一天」，点日期再展开选择；历史与回收站降为次级入口。保留至少 44pt/48dp 触控范围，减容器留白而非缩小触控目标。证据：`screens/ios-en-light-diary.png`、`screens/android-en-dark-diary.png`；`DiaryScreen.tsx:60–75`。
2. **P1 · 一次称重被表达成 +0.0 kg 的变化。** 原生页面同时显示巨大 `+0.0`、数据不足和 `1 weights`。不是体重计算错误，而是缺少比较基础时仍使用变化指标的表达缺陷。仅一次记录显示「已记录 80.4 kg · 10/7，等待更多记录」；两个不同日期后才显示变化，趋势的最低数据条件单独说明。证据：`screens/ios-en-light-progress.png`、`screens/android-en-dark-progress.png`；`core/src/insights.ts:103–111`、`InsightsScreen.tsx:117–139`。
3. **P1 · Android 无障碍操作与视觉按钮不一致。** Me 的 Settings 节点有名称和焦点，但 `clickable=false`，动作列表没有 `ACTION_CLICK`；官方自动化实际点击失败，普通触控随后成功。Today 三个记录入口在本轮导出的 Android 树中也缺少具名节点。先修复宿主实际暴露的按钮角色、点击动作、选中/禁用状态，再做视觉微调。证据：`accessibility/android-en-dark-me.json`、`accessibility/android-en-forms-today.json`、`android-accessibility-click-failure.json`；`MeScreen.tsx:17–21`、`QuickActions.tsx:5–20`。本轮没有运行 TalkBack，不扩大为完整读屏失败结论。
4. **P1 · 份量页保住了按钮，却丢失了决定上下文。** 数字键盘打开时能看到 150 g 和「添加」，选中的食物名与完整餐次选择却不在可见区域。新增运动先展开长目录，时长藏在下方。固定紧凑的「食物名 · 日期/餐次」上下文，输入与即时估算相邻；运动先选/显示当前活动，再输入时长，目录作为替换动作。证据：`screens/ios-en-food-portion-keyboard.png`、`screens/ios-en-exercise-new.png`；`FoodSheet.tsx:768–846`、`ExerciseSheet.tsx:128–181`。
5. **P1/P2 · 关系品牌还没有连接到任务主线。** Partner 的大图形、欢迎标题、介绍先于连接状态和下一步；Today 则叠加标题、模式说明、品牌、三色记录动作与大摄入卡。建议把「我今天做什么」「我们如何互相支持」作为主线，连接状态与下一步先出现，温和品牌退为轻量背景。证据：`screens/ios-en-light-partner.png`、`screens/ios-zh-light-today.png`；`PartnerScreen.tsx:28–52`、`App.tsx:769–778`、`TrackingTodayScreen.tsx:20–28`。

## 应保留的好设计

原生底栏形态、图标、标签、选中胶囊与反馈均作为已认可基准，保留其导航逻辑。
暖纸画布、石墨正文、开放次级区域、明确单位、直接记录入口及真实宿主字段保留。
浅深色主题已经跨两端真实渲染，不建议重新换一套主题。
保留未记录与读取失败的诚实区分、仅记录模式、食物汇总可能不完整的解释、就地范围校验、固定表单行动、草稿/冲突机制，以及可恢复删除。
保留按日期布点、真实拟合线与缺测标记；本轮没有检验健康建议公式，不因设计评审改变安全限制。
保留 Partner 的默认私密和明确同意边界；账号、共享及迁移是否完成依实际流程验收，不能靠视觉假装。

## 统一、克制的方向与 token 建议

方向是「两个人的安静日常伙伴」：帮助完成一件小事、理解已有记录、在明确同意下相互支持。
一屏一个主任务和一个主摘要；主卡只用于真正的摘要或任务边界，其余用开放行和分隔。
关系温度来自语言、状态和轻量成对图形，不来自满屏玻璃、庆祝动效或竞争分数。
底栏保持原样；内容主行动建议使用其 navigation 绿色，现有类别色用于小标签/图线，现有紫色品牌用于关系表达。
这是设计判断与待验证起始值，不是已实施方案，也不是用户已批准的新配色。

| ink / secondary | #28242C / #69616B | #FAF5F3 / #CEC3CE | 沿用；解释不靠低透明度 |

建议间距 4/8/12/16/24/32；屏幕边距 20–24pt/dp，章节间 24，章节内 8–12，普通字段 12–16。
标题 24–27 / 600，章节 18 / 500–600，正文 16 / 400，辅助 14 / 400；主展示值 36–44 / 500，普通输入 18–24 / 400–500。
统一等宽数字与单位基线；不要将体重输入当 KPI 巨字。
卡片圆角 18–22、按钮/字段 10–12，保留底栏当前圆角。
不能将上述 CSS px/rpx 自动等同于物理 pt/dp/sp；大字、换行和实际触控范围必须在宿主验证。

本轮读取的 [Android 官方无障碍指导](https://developer.android.com/guide/topics/ui/accessibility/apps) 建议移动触控目标至少 48×48dp，小字号文字对比度至少 4.5:1，并让描述表达控件用途与结果。
这些是验收约束，不是要把 LeanOn 套成通用 Material 页面。
Apple HIG 页面仅返回需 JavaScript 的提示，因此没有以未读正文支撑具体条款；iOS 44pt 是建议验收目标，非本轮全面测量结果。
当前截图不足以声称完整对比度或无障碍通过；抗锯齿像素、遮罩、SVG、焦点、禁用、键盘与读屏需各自检查。

## 改造顺序与验收边界

1. **先处理可信状态与实际可访问性。** 修单点变化表达；统一缺失、加载、错误和缓存状态；核对原生按钮角色/点击/选中/禁用。不会动底栏。
2. **再做 Diary 与 Today 的信息减法。** 日期行、日摘要和记录入口优先；去掉重复开场/状态，设置和完整营养成为次级信息。
3. **统一新增/编辑的字段与行动。** 食物上下文、运动目录、数字/单位、键盘上的行动区、就地错误；保留冲突和草稿行为。
4. **收束 Partner、Me、Settings。** 关系状态先于介绍，资料变短，管理详情分层，列表间距统一。
5. **完善图表与双语言打磨。** 多点/稀疏/单点/空、日期和单复数；浅深色、中文/英文、小屏/大字、减少动态和辅助技术真实回归。
